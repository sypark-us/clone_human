## Browser journeys

1. Fresh player opens the launch screen, starts a run, dismisses onboarding, relocates a machine to another terrain zone, drafts into an empty slot, chooses a route, starts/pauses combat, advances one turn, reloads, and resumes the exact paused snapshot.
2. A deterministic reference strategy completes all eight waves through real UI controls, including rewards, upgrades and result screens. The browser clock advances normal game timers; state is read back from the real local save after actions.
3. 390×844 viewport: keyboard tile movement, no document-wide overflow, canceled restart preserves progress, twelve-item module guide opens and closes.
4. Storage quota failure: persistent in-game warning is visible at phone width; gameplay stays available.
5. Corrupt save: original bytes remain untouched until the player explicitly begins a new game.
6. Audio: no context exists before player interaction, opt-in starts a running native AudioContext and oscillator output, music/effects preferences persist separately. Unit checks cover immediate bus mute and hidden-tab suspension.

The first-player test fixes the random seed through a test-only browser initializer so legitimately powerful first-turn wins do not make the pause/restore test nondeterministic. The complete-run test starts from a serialized fresh-run fixture generated by the real engine; every subsequent game action is a browser click. Neither fixture is used by the shipped game.

## Practical limits

Chromium desktop/mobile emulation is verified. Physical iOS/Android touch and listening quality, other browser engines, assistive-technology walkthroughs and long-term balance require further playtesting. A reference strategy wins consistently; randomized legal play also produces losses. This is evidence of playable progression, not proof that every build is equally strong.

A GitHub Actions template is provided at `docs/github-actions.yml`. GitHub rejected adding an active workflow because the current OAuth app lacks workflow scope; no credentials or permissions were changed. The template can be installed at `.github/workflows/test.yml` using an authorized connection. No remote CI run is claimed. No Pages settings, main-branch merge, or live deployment is included in the implementation.
